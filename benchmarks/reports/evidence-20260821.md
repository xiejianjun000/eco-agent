## 三、暴露的问题与修复

### 3.1（已修复）heartbeat.py 硬编码 `~/.eco`，mem_cron 只读库报错

**症状**：smoke 运行全程 116/116 次心跳的 `mem_cron` 步骤均返回
`{'vacuumed': 0, 'integrity': 'error'}`，stderr 每跳刷一条
`[Pulse] mem_cron hybrid_vectors.db: attempt to write a readonly database`。

**根因**：`agent_core/heartbeat.py` 的 `default_steps()` 硬编码
`Path.home() / ".eco"` 作为 SQLite 目录，本机沙箱对工作区外（`~/.eco`）
只读，`VACUUM` 写入被拒。

**修复**（最小改动，对齐 `agent_core/workspace.py` 的 ECO_DIR 口径）：

```diff
-        eco_dir = Path.home() / ".eco"
+        eco_dir = Path(os.environ.get("ECO_DIR", str(Path.home() / ".eco")))
```

**验证**：`ECO_DIR` 指向证据目录后，`default_steps()._dbs == []`，
`step_mem_cron()` 返回 `{'vacuumed': 0, 'integrity': 'ok'}`（优雅跳过）。
`tests/modules/test_pulse_steps.py` 14 项全绿。

### 3.2（发现，本轮未修）版本快照保留逻辑 bug — 新快照被立即删除

**现象**：进化事件中 `version_snapshot` 指向 `v251`/`v252`，
但 `versions/` 目录最终只保留 `v88`/`v93`/`v98`（运行前旧版本），
v251/v252 快照反而不存在；事件中 `version_snapshot_exists: False`。

**根因**：`meta_evolution._self_versioning()` 用
`sorted(iterdir())` 做**字典序**排序，`"v251" < "v88"`（字符 `2 < 8`），
导致“保留最近 3 版”的清理把刚建好的最新快照当“最旧”删掉。

**建议修复**：按版本号数值排序（`int(p.name.lstrip("v"))`）再清理。

### 3.3（发现，本轮未修）verify_ops 进化报告路径口径不一致

`_scripts/verify_ops.py` 检查 `ROOT / "evolution_report.md"`（未版本化，
不存在），而实际进化产出为 `memory-tree/obsidian_sync/quality/evolution_report_v{N}.md`。
故 verify_ops 的“进化报告”项恒报 `exists: false`，属口径 bug 而非“未进化”。
