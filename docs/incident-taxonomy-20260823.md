# eco-agent 事故维度化复盘 —— 从"点修"到"契约治理"

> 日期：2026-08-23 · 起因：军哥要求"不要发现一个问题解决一个问题，要看是哪个方面出了问题"

## 一、今天全部事故的维度归档

把 15+ 起事故按"能力管线"五个环节归类，每类的根因都是**同一个隐式假设被打破**：

### 维度 A：配置/环境层（"环境一定就位"）
| 事故 | 被打破的假设 |
|------|-------------|
| "no api key" 两连发 | 单例构造时环境变量必已注入 |
| 路径漂移 .eco-ws/.eco-live | 两个目录语义会自动一致 |
| 凭证缺口（在线监测/排污许可/GitHub/腾讯） | 挂了工具就等于配了凭证 |

### 维度 B：接线/注册层（"名字和格式不会变"）
| 事故 | 被打破的假设 |
|------|-------------|
| MCP 带点工具名 slug 折叠 | 远程工具名不含点号 |
| mcp__ 分发分支漏腾讯前缀 | 新 server 会自动被分发 |
| PERMISSION.md 解析漏 31 项 | yaml 块里不会有注释行 |
| streamablehttp 三元组 | 所有传输 __aenter__ 都返回二元组 |

### 维度 C：数据/契约层（"远程行为符合声明"）
| 事故 | 被打破的假设 |
|------|-------------|
| 腾讯 search_file schema 校验拒收 | 远程返回类型符合它自己的声明 |
| execute_code 结果 2000 字截断 | 分析类输出不会超长 |

### 维度 D：治理/溯源层（"审计会自动覆盖一切"）
| 事故 | 被打破的假设 |
|------|-------------|
| 工具调用序列不入事件日志 | 消息落盘就等于全量审计 |
| .eco-live 残留目录 | 迁移就是删除 |

### 维度 E：模型行为层（"模型会按工具表行动"）
| 事故 | 被打破的假设 |
|------|-------------|
| 说"未挂载"/让用户确认环境 | 模型会自查工具表 |
| 列已删除文档 | 模型会区分历史与现状 |
| 凭记忆断言条例未出台 | 模型不会用先验压过事实 |
| 过程外泄/菜单病 | 模型知道"答案"与"工作日志"的边界 |
| 技能禁用领域触发注入检测 | 安全规则措辞不会自伤 |

## 二、为什么我知道这么操作（把套路显性化）

每次我做的其实是**同一套四步**，它的名字叫**契约式治理**：

```
1. 定位被打破的"隐式假设"（5 Whys 归到根因）
2. 把假设显性化：变成一道可自动检查的契约
3. 给契约配守护机制（四选一或组合）：
   ① 体检   —— 健康自检定期报（health_check）
   ② 测试   —— 交叉校验/回归测试锁死（test_capability_consistency）
   ③ 容错   —— 运行时校验降级/自愈（惰性刷新、宽松校验、块切片解析）
   ④ 规程   —— 行为规则（规则 13-17）
4. 同类事故以后归同一维度处理，不再单独打补丁
```

这不是我的发明——是软件工程的成文纪律（Design by Contract、fault taxonomy），DSH 本体（插件契约/事件溯源/权限闸门）也是同一哲学。

## 三、五维度的闭环状态（缺口 = 下一步）

| 维度 | 已有守护 | 状态 |
|------|---------|------|
| A 配置层 | health_check + setup_credentials + 客户端自举 | ◐ 半闭环：缺"运行时报 401/凭证失效时的自愈引导" |
| B 接线层 | 交叉校验测试 + slug 回归 + 分发泛化 | ● 已闭环 |
| C 契约层 | 输出校验降级 + 结果长度提升 | ◐ 半闭环：远程 schema 变化无监控 |
| D 溯源层 | tool/call 入链 + audit_tail/session_log_tail | ● 已闭环 |
| E 行为层 | 规则 13-17 | ◐ 半闭环：规则是概率性的，缺机制级确定性拦截 |

## 四、按维度补缺（不再点修，一类一堵）

1. 【A】凭证失效自愈：LLM/MCP 401 时返回"配置指引 + setup_credentials 入口"，而非裸报错
2. 【C】契约漂移监控：health_check 增加"远程工具数/关键工具存在性"基线比对，腾讯文档 205 工具突然变 100 就报警
3. 【E】机制级拦截：法规时效类提问（"出台/废止/施行"）强制先过 web_fetch/检索管道再答（确定性预检，不靠模型自觉）
4. 【D→CI】把 run_evals 机械门禁 + audit 全库自审接进 redeploy.sh 与日常巡检，让"每天自动跑"替代"我手动跑"

## 五、A-E 全维补全落地记录（2026-08-23）

| 维度 | 补的契约 | 实现 |
|------|---------|------|
| A 配置 | 凭证失效自愈指引 | `_llm_error_reply`：no api key→setup_credentials 入口；401/403→更新密钥；402→充值提示（两个错误出口全接） |
| B 接线 | MCP 配置可见性 | health_check 新增"MCP 接线"行（4 个 server 清单） |

| D 溯源 | 审计链完整性自检 | health_check 新增"SM3 审计链 N 条 完整可验证"（verify_chain） |
| E 行为 | 法规时效确定性闸门 | `_law_status_trigger` 正则识别出台/废止/施行/时效类提问；模型首轮未调用核实工具即下结论 → 强制补核实轮（机制级，不靠规则自觉） |
