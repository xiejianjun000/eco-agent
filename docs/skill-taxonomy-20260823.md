## 分层模型

```
元技能层  meta-audit（技能自审）/ meta-test（技能自测）/ meta-interview（访谈冷启动）
原子层    atom-constitutive（构成要件）/ atom-evidence-chain（证据链）/ atom-discretion（裁量）
场景层    执法实务矩阵（见下）
```

## 场景层孵化矩阵（巡查 × 文书 × 评查）

公式：**程序节点 × 案由**，粗算 60-100 个场景技能，按优先级分批：

| 优先级 | 程序节点 | 案由/主题 | 预计技能数 |
|--------|---------|-----------|-----------|
| P0 | 文书制作 | 现场检查笔录/询问笔录/责令改正/处罚告知/处罚决定/结案 | 6 |
| P0 | 案卷评查 | 程序合规审查/证据链审查/裁量审查/文书要素审查 | 4 |
| P1 | 现场巡查 | 废水超标/废气超标/危废无证/暗管偷排/篡改数据/未批先建 | 6 |
| P1 | 处罚执行 | 按日计罚/查封扣押/停产整治/强制执行 | 4 |
| P2 | 复议应诉 | 行政复议答复/行政诉讼应诉 | 2 |
| P2 | 督察整改 | 督察整改方案/销号验收 | 2 |

每个场景技能 = 原子技能的组合编排 + 该节点的时限表/文书要素表（照 Greater-China-Legal 的 environmental-administrative 样式）。

## 技能孵化纪律（G7 技能孵化）

1. 同一操作使用 3 次 → 用 meta-interview 访谈式固化（问军哥 8 个问题出骨架）
2. 新技能必须过 meta-audit（评分 ≥ 70）才进 ecoskills/
3. 每个场景技能必须有：触发词 / 工作流步骤 / 决策表 / 禁用领域 / 输出格式（五段式，见原子技能）
4. 高危技能（涉处罚/移送）risk_level=high，必须含"禁用领域"块

## 元技能闭环（自举）

```
meta-interview（问军哥）→ 生成技能骨架 → meta-audit（自审打分）
→ meta-test（自测用例+黄金要点）→ evals/ 评测集 → CI 硬门禁
```
