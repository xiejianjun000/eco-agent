# 垂直行业领域 Agent 应该如何开发 —— 四平台调研 + 深度思考

> 日期：2026-08-23 · 调研渠道：GitHub / X / 掘金 / 知乎 + VC 研报
> 目标：为 eco-agent（生态环境执法垂直 Agent）提炼可落地的方法论与差距清单

---

## 〇、一句话结论

**垂直 Agent 的胜负手不在模型，在"领域脏活"：行业数据壁垒 + 业务系统直连 + 领域评测闭环 + 合规信任。通用模型只解决 20%，剩下 80% 是知识工程、工具封装、评测与安全——而这些正是没人愿意干的"脏活"，也是护城河。**

### 1. 垂直行业开源生态成熟度排序

| 行业 | 成熟度 | 代表 |
|------|--------|------|
| 法律 | ★★★★★ 最成熟 | LegalAgentBench（评测）/ J1Bench（ACL 2026 交互式评测）/ Legal-world（全生命周期环境）/ Greater-China-Legal（**478 个 Skills**）/ awesome-legal-skills |
| 医疗 | ★★★★ | MedQA 评测 + GraphRAG 多智能体会诊（Chinese-MedQA-Qwen2） |
| 政务/监管 | ★★ 零星 | gov-agentic-AI（角色编排+可审计+HITL+可移植技能）、regulated-ai-governance（CrewAI/AutoGen/LangChain 适配器强制合规策略） |
| 环保/执法 | ★ **几乎空白** | 搜 "environmental agent" 全是游戏/模拟器杂项——**蓝海，无范本可抄** |

### 2. 从法律生态提炼的四大模式（可移植到执法）

1. **评测基准先行**：harvey-labs 用 benchmark 驱动迭代；Legal-world 提供"咨询→文书→庭审"全生命周期交互环境
2. **技能模块化（Skills）**：478 个场景技能、task-level rubric（评分标准）盲评——与 eco-agent 的 ecoskills 完全同构
3. **编排器 + 专家子代理**：iblai 律所助手 = 1 编排器 + 12 专业子代理
4. **审计 + HITL 内置框架层**：政务仓库把可审计性、人工复核、策略执行做成框架能力，而非事后补丁

### 3. 反面教材（GitHub 上的坑）

- **空壳模板泛滥**：搜 vertical ai agent 大量 0-11★ 仓库只有 README/模板，无数据无评测不可复现
- **通用 RAG 硬套行业**：大量 2-15★ 课程作业式 demo，缺领域评测与检索质量验证
- **两个极端**：纯规则（32 tests zero LLM cost，缺灵活性）vs 无闸门纯 LLM（缺约束）——执法场景必须在中间：规则保底 + LLM 灵活 + 闸门兜底

## 二、VC/产业共识（CRV、Galen、VNTR、svtr、CB Insights、YC）

| 来源 | 核心论点 |
|------|---------|
| YC Lightcone（Garry Tan 等） | **垂直 Agent 市场是 SaaS 的 10 倍**——吃人力预算而非软件预算，卖"完成的工作"而非席位，单品类可出 $300B 公司 |
| YC（Jared） | 切入点找**枯燥、重复的行政工作**（政府合同投标/催收/QA 测试） |
| CRV《Vertical AI Companies》 | 行业专家知识 > 通用模型能力；价值在"领域 know-how + 数据 + 分发"三合一 |
| svtr《护城河藏在脏活里》 | 护城河 = 数据整理、标注、工作流嵌入这些没人愿干的脏活 |
| Trunk Tools（VentureBeat） | 建筑行业**弃用通用模型、自研垂直栈**，文档审查 **60 天 → 10 天** |
| Chai Discovery（CB Insights） | 垂直准确率 **96% vs 通用 46%**；15 个月估值 13 亿美元 |
| Bret Taylor / Sarah Guo | 押注垂直 AI：Agent 是品牌新前门，企业软件未来属于垂直 Agent |
| XTrace / a16z | **模型是商品，护城河在最后一公里** = 集成 + 工作流 + 专有数据三杠杆 |
| 反方（F-Prime、Yutori） | 基础模型厂已做产品（Claude Cowork/Codex）；垂直玩家死于**错误复利**；威胁还包括企业内自建"影子 Agent" |

**共识公式**：垂直价值 = 领域数据壁垒 × 工作流嵌入深度 × 评测可信度 × 合规信任

**四个致命坑（英文世界反复强调）**：
1. **安静失败**：Agent 照做但做错（错发/错删/错下结论）且中间无人拦截——guardrails 必须卡在"决定"与"执行"之间
2. **95% 试点死于集成/工作流/治理**，几乎从不因为模型不够聪明
3. **MCP 集成正在商品化**：靠集成进门但不可依赖，要尽快沉淀工作流锁定 + 专有数据
4. **审批疲劳**：对无风险动作也加审批 → 团队机械点"同意" → 关键审批失效。**按"做错 100 次的代价"分级设门**（我们的 L1-L4 正是此设计，需复核分级是否合理）

## 三、掘金中文社区方法论（10 篇原文精读）

**核心共识**：
1. **垂直胜负在"最懂行业的团队"**：五阶段法——定义问题 → 知识本体 → 专家在环 → 评测监控 → 持续迭代
2. **强监管场景用"静态工作流"而非自主 Agent**：预定义路径、可审计决策链；政务/金融/医疗不依赖 LLM 自主规划（立案→调查→处罚→复议链路固定）
3. **知识本体化 + 混合检索**：实体/关系/标准术语表 + BM25 精确 + 向量语义 + 图谱扩展（防"检索漂移"）
4. **评测是最大卡点**：黄金标准集 + 过程评测（高风险场景）+ LLM-as-Judge（有偏差需锚点校准）+ 人工抽检，分层搭
5. **工程化 > 模型**：沙箱隔离、持久化执行、RBAC 多租户、审计、限流熔断、可观测是投产前提（字节 DeerFlow：三层沙箱 + 分层 Memory + 10 万并发）

**执法场景直接可用**：专家在环反馈飞轮（每条处罚建议点对/错/部分对并注明理由→回流知识库）、强制引用溯源、涉密案卷多租户隔离、真实案卷做黄金标准集（重点评程序合法性/裁量准确性/法条引用正确性）

**坑**：agent washing（约 40% 项目被取消）；90% 时间耗在评测调优；开源平台测试覆盖为零/沙箱可被隐私攻击

## 四、知乎深度讨论（高赞观点）

_（知乎直连 403 反爬，正文经腾讯云镜像/聚合长文读取，均已标注原始出处）_

- [AI Agent 最大的机会在传统行业"老师傅"手里](https://www.zhihu.com/question/1983975700521301879)——领域专家把隐性经验喂给 Agent 才是壁垒（30 万围观、170+ 回答的集中讨论）
- [一文解决政企 Agent 三大难题：成本、效果、安全](https://zhuanlan.zhihu.com/p/2046701295105578667)——瑭宋元专栏
- [企业 Agent 从试点到大规模应用](https://www.zhihu.com/question/2046215887649297114/answer/2046701561716510962)

**知乎最强共识**：
1. **护城河不在模型，在场景 Know-How + 知识库迭代闭环**——模型可换，行业认知不可复制
2. **幻觉是致命伤**：司法 AI 已出现虚构法条/案号事故 → 强制溯源 + 独立校验层是底线
3. **安全必须架构内置**：角色分层授权、等保三级/国密算法(SM2/3/4)/三员分立/审计日志≥6月，事后补丁不算数
4. **从 SOP 化 Skill 切入**，而非上来就做万能 Agent——把固定业务流程（如案卷评查清单）技能化
5. **成本黑洞**：数据清洗占项目周期一半以上（清洗正则可写两千行）；约 90% Token 被无价值上下文浪费；**3-5% 幻觉率在生产不可接受**；某地税务 Agent 月烧 23 万、解决率 <50% 被叫停
6. **RAG 三死穴**（瑭宋元）：从零推导无积累 / 只匹配碎片难连点成线 / 粒度混乱——**"知识库腐烂比没文档更危险"**，好回答必须反哺知识库
7. **"专家团队"分工**：简单分类/抽取用 7B/14B 小模型，复杂逻辑才用旗舰，本地路由引擎省钱降延迟
8. **来源三类标注**：回答必须标注「原文 / 数据库 / 生成」三类来源，司法场景尤其如此

## 五、垂直 Agent 六层架构模型（综合归纳）

```
L0 知识工程  领域数据(法规/案例/专家经验) → 结构化 KB + 知识图谱(GraphRAG 多跳)
L1 工具层    业务系统直连(MCP 标准化契约；政务平台逆向封装=自研垂直栈)
L2 编排层    Manager-Specialist 子代理 · 会诊式多agent · 执法阶段状态机
L3 安全层    权限闸门(L1-L4) + 人工确认(HITL) + 全量审计链("策略=可执行代码")
L4 评测层    领域 benchmark + 任务级 rubric · 回归防退化 · CI 硬门禁
L5 进化层    技能孵化(3次使用→技能) · 专家经验沉淀 · 教训自愈闭环
```

## 六、六条开发铁律

1. **评测先行**：先建领域 eval（案卷评查/法条适用/文书规范），再动提示词——每次改动过回归
2. **知识工程占 80%**：脏活（数据整理/标注/图谱）才是护城河，模型只占 20%
3. **工具直连业务系统**：能 API 就不模拟点击；政务平台无 API 就逆向封装成 MCP（Trunk Tools 式垂直栈）
4. **人机协同内置**：HITL + 审计链 + 拒绝不说教必给替代方案——信任是 ToG 的生命线
5. **技能模块化可移植**：经验沉淀为可插拔 Skills（rubric 化），不写死在提示词里
6. **垂直自研 > 通用套壳**：量级差距案例（60→10 天、96% vs 46%）都来自垂直数据+工具，不是模型名

## 七、eco-agent 对照体检（已具备 / 缺口）

**已命中**（过去两天的建设恰好踩在最佳实践上）：
- L1 工具层：三大政务平台直连 + 腾讯文档/GitHub/知识库 MCP（205+ 工具）
- L2 编排层：子代理/工作流/目标/执法三阶段状态机
- L3 安全层：L1-L4 权限闸门 + SM3 审计链 + 注入校验 + HITL 审批栈
- L5 进化层：ecoskills 技能孵化 + lessons 自愈 + 建议引擎
- L4 评测层（部分）：测试框架 + 能力一致性交叉校验 + 红线断言

**缺口（按优先级）**：
1. 【P0】执法领域评测集：案卷评查/法条适用/文书规范三套 eval（45 题基线待落地）+ CI 硬门禁（安全断言阻断发布）
2. 【P1】知识图谱化：法典 1242 条 → GraphRAG（条→引用→罚则→裁量 多跳），当前是条文级检索
3. 【P1】专家经验显性化：把军哥的裁量经验/案卷评查标准沉淀为 rubric 化技能（对标 478 Skills 的法律生态）
4. 【P2】垂直小模型分工：高频任务（文书生成/台账汇总）用 deepseek-v4-flash 或蒸馏小模型降本，复杂推理走 v4-pro
5. 【P2】行业化 UI：执法驾驶舱（案卷台账/在线监测/任务闭环 一站式），现在是通用聊天+面板

## 八、路线图（eco-agent 三步走）

1. **近期（评测闭环）**：三套执法 eval 集 + 测试框架接入 CI 硬门禁 → 每次改动有量化回归
2. **中期（知识深挖）**：法典 GraphRAG + 案卷评查 73/75 模板技能化 + 执法经验 rubric 沉淀
3. **长期（垂直栈）**：文书/台账垂直小模型 + 执法驾驶舱 UI + 对内复制到其他执法分局
