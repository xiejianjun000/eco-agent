# 跨平台开发配置（macOS ↔ Windows 10）

> 结论先行：**只用一个仓库**（`git@github.com:xiejianjun000/eco-agent.git`），
> 不要为 Mac 和 Win10 各建一个。两个仓库会立刻带来双向同步、分支分叉、
> 冲突合并三重负担，而跨平台差异用 `.gitattributes` + 各机一次性配置就能解决。

---

## 一、为什么是一个仓库

| | 一个仓库（推荐） | 两个仓库 |
|---|---|---|
| 同步 | `git pull` / `git push`，Git 原生 | 需手工 remote 对拉或写同步脚本 |
| 历史 | 单一线性历史，`git log` 可信 | 两条历史，追溯困难 |
| 冲突 | 正常合并 | 双向同步冲突，极易丢改动 |
| CI | 一套流水线 | 两套，且可能结论不一致 |

平台差异（换行、路径、可执行位）属于**文件形态**问题，Git 早有标准解法，
不需要靠"拆仓库"来回避。

---

## 二、仓库侧配置（已完成，随代码提交）

### `.gitattributes`

统一契约：**仓库内部一律存 LF**，工作区形态各平台自便。

- `*.sh` / `*.py` / `*.yml` 等 → 强制 `eol=lf`
  （否则 Win 提交的 CRLF 会让 Linux/容器报 `bad interpreter: /bin/bash^M`）
- `*.bat` / `*.cmd` / `*.ps1` → `eol=crlf`（Windows 原生脚本需要）
- 图片/字体/压缩包/数据库 → `binary`，禁止任何换行转换

### 历史遗留已归一化

原仓库有 **16 个文件混着 CRLF**（两台机器来回改的典型症状）。
已执行 `git add --renormalize .` 统一为 LF，并逐文件哈希比对确认
**仅换行变化、内容零改动**。

## 三、各机一次性配置

### Windows 10

```powershell
# 1) 换行：检出转 CRLF，提交转 LF（配合 .gitattributes 使用）
git config --global core.autocrlf true

# 2) 支持超长路径（Win 默认 260 字符限制，本仓库层级较深）
git config --global core.longpaths true

# 3) 中文文件名正常显示（本仓库 docs/ 与 ecoskills/ 有大量中文名）
git config --global core.quotepath false

# 4) 文件名大小写敏感（防止 Foo.py 与 foo.py 被视作同一文件）
git config --global core.ignorecase false
```

> **同时需要**：Windows 系统层也要开长路径支持，否则 `core.longpaths` 单独无效。
> 管理员 PowerShell 执行：
> ```powershell
> New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" `
>   -Name "LongPathsEnabled" -Value 1 -PropertyType DWORD -Force
> ```
> 改完重启生效。

### macOS

```bash
# 检出保持 LF，提交时把意外混入的 CRLF 转掉
git config --global core.autocrlf input

# 中文文件名正常显示
git config --global core.quotepath false

# macOS 文件系统默认不区分大小写，显式开启敏感以对齐 Linux/CI
git config --global core.ignorecase false
```

## 四、Win10 侧环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| Python | **≥ 3.10** | `pyproject.toml` 声明；3.9 会因 `X \| None` 类型标注在导入期报 `TypeError` |
| 依赖 | `pip install -r requirements.txt` | |
| 编码 | 建议设 `PYTHONUTF8=1` | Win 默认 GBK，读中文源码/数据易乱码 |

```powershell
# 建议加进系统环境变量，避免每次手设
setx PYTHONUTF8 1
```

### 已知平台差异：`shell_run`

`agent_core/exec_tools.py` 的 shell 白名单是 POSIX 命令集
（`ls`/`cat`/`grep`/`find` 等），**Windows 上大部分不可用**。

但这不影响取证能力——`grep` / `glob` / `file_read` / `api_probe`
四个工具均为纯 Python 实现，不走 shell，跨平台一致。

若确需在 Win 上用 shell，建议在 Git Bash 或 WSL 中运行本项目。

## 五、上手流程

### Win10 首次克隆

```powershell
git clone git@github.com:xiejianjun000/eco-agent.git
cd eco-agent
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

# 跨平台自检：12 项断言，全过打印 ALL PASS
python _scripts\win10_selfcheck.py
```

### 日常协作

```bash
git pull --rebase    # 拉取前先 rebase，避免无谓的合并提交
# ... 改代码 ...
git add -A && git commit -m "..."
git push
```

## 六、验证换行配置是否生效

任一平台执行，确认工作区没有意外的换行改动：

```bash
# 应无输出（有输出说明换行配置不对）
git diff --stat

# 查看某文件的实际属性
git check-attr text eol binary -- agent_core/exec_tools.py
# 期望：text: set / eol: lf / binary: unspecified
```

如果 `git status` 显示大量"整文件被修改"但 `git diff --ignore-all-space`
为空，即为换行问题——重新执行本文档第三节的配置，再 `git add --renormalize .`。
