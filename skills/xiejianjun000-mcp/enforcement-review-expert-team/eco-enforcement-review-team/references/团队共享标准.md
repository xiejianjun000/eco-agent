# 团队共享标准

> 所有 Agent 在未单独定义时，默认遵循本标准。

---

## 一、交接模板（Handoff Template）

所有组团成员向调度官回传结论时，必须使用此格式：

```
═══════════════════════════════════════
  专业审查报告: [审查维度]
═══════════════════════════════════════

发送方: [Agent ID]
接收方: enforcement-review-lead
日期: [自动填充]
案号/任务: [案号或任务标识]

【核心结论】（一行）
[程序合法 / 基本合法需补正 / 存在重大问题]

【审查依据】
1. [法条1]: 《法律名称》第X条第X款: "原文"
2. [法条2]: ...

【发现问题】（如有）
├─ [问题1] (严重程度: 🔴高/🟡中/🟢低)
│   ├─ 事实: [具体描述]
│   ├─ 依据: [违反了什么规定]
│   ├─ 证据: [案卷第X页/数据时间戳]
│   └─ 建议: [可操作的整改建议]
└─ [问题2] ...

【证据清单】
├─ 证据1: [类型] [来源] [证明内容]
└─ 证据2: ...

【置信度】
├─ 直接证据比例: X/Y
├─ 推断比例: X/Y
└─ 需要补证的项目: [如有]

【风险预警】
├─ 败诉风险: 🔴高/🟡中/🟢低
├─ 移送风险: 是/否
└─ 时效风险: 剩余 X 天

═══════════════════════════════════════
```

## 二、质量门禁（Quality Gate）

每个审查阶段结束前，调度官必须通过以下门禁才能进入下一阶段：

### QG1: 预审门禁（Phase 1 → Phase 2）

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 任务类型明确 | 至少归类到"评查/执法/督察/综合"之一 | 反馈用户确认 |
| 管辖权确认 | 属地 + 级别均已确认 | 补充管辖权分析 |
| 时效验证 | 追责期限未超（危害后果5年/其他2年） | 标注超期风险 |

### QG2: 分析门禁（Phase 2 → Phase 3）

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 团员回传完整 | 所有指定团员均已 SendMessage 回传 | 重试1次（5分钟）→ 降级跳过 |
| 法条引用完整 | 每条结论含法规名称+条款号+原文 | 要求团员补充 |
| 无自我矛盾 | 不同团员对同一事实认定不冲突 | 调度官仲裁 |

### QG3: 综合门禁（Phase 3 → Phase 4）

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 25项全检 | 扫描引擎已遍历全部25项 | 回退补充扫描 |
| 法条双标注 | 所有法条含老法+法典对照（过渡期内） | 补充标注 |
| 逻辑闭环 | 事实→违法要件→法律后果链条完整 | 补充论证 |
| 无推理跳跃 | 不存在"据推断…所以违法"的裸结论 | 补充证据或降低置信度 |

### QG4: 输出门禁（Phase 4 → Phase 5）

| 检查项 | 标准 | 不通过处理 |
|--------|------|-----------|
| 报告完整性 | 含8模块（概述/依据/维度/否决/问题/评分/建议/法条链） | 补充缺失模块 |
| 问题可追溯 | 每个问题含法条引用+事实依据 | 补充依据 |
| 格式合规 | docx符合公文格式（A4/标题/页码） | 重新排版 |

## 三、证据标准

### 3.1 默认怀疑主义原则

> **"不通过"是默认状态。要拿到"通过"，必须具备压倒性证据。**

### 3.2 证据等级

| 等级 | 定义 | 置信度 |
|------|------|--------|
| L1 直接证据 | 现场笔录、监测报告、现场照片、CEMS原始数据 | 高 |
| L2 间接证据 | 台账记录、运行记录、证人证言、推断结论 | 中 |
| L3 推断 | 经验判断、类似案例、合理怀疑 | 低（需补证） |

### 3.3 自动失败触发词

当审查结论中出现以下表述时，**自动判定为不通过**：

- "未发现问题"（无具体检查项列表）
- "全部合规"（无逐项核实记录）
- "完美/满分"（无证据支撑）
- "应该/可能/大概"（不确定表达且无补证计划）

## 四、上下文预算管理

### 4.1 预算分配

| Agent | 预算上限 | 策略 |
|-------|---------|------|
| 调度官 | 上下文 60% | 最高，需持有全局视图 |
| 案卷评查专家 | 上下文 25% | 需加载案卷文本，可外部化 |
| 其他团员 | 上下文 15% | 轻量，只接收任务+回传结论 |

### 4.2 超预算应对

1. **压缩**：历史对话摘要为关键结论（≤500 tokens）
2. **外部化**：大文本写入临时文件，用路径引用
3. **分段**：超长案卷分段审查，每段独立评分后汇总
4. **降级**：非关键维度跳过，标注"降级处理"

## 五、失败模式目录

| 编号 | 失败模式 | 症状 | 应对 |
|------|---------|------|------|
| F1 | 法条过时 | 引用了2026-08-15后已废止的法律 | 激活 legal-transition 校验 |
| F2 | 证据幻觉 | 声称有证据但实际案卷中不存在 | 调取案例文本交叉验证 |
| F3 | 循环否决 | 否决引擎反复标记同一问题 | 去重后只保留首次命中 |
| F4 | 团员沉默 | 指定团员未在时限内回传 | 重试1次→降级跳过→标注 |
| F5 | 分支爆炸 | 法律分支逻辑组合爆炸 | 限定同时激活的分支数≤3 |
| F6 | 上下文溢出 | Token 超过预算 | 触发 4.2 应对策略 |
