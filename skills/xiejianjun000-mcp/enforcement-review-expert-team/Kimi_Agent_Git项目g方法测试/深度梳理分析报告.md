## 一、项目是什么

这是一个名为 **EcoAegis 生态环境执法办案评查一体化平台** 的资料包，由三类内容组成：

1. **前端工程骨架（app/）**——React 18 + Vite 5 + TypeScript strict + 纯 CSS 的三栏式工作平台雏形；
2. **设计文档体系（design/）**——14 份 Markdown，含 1 份全局设计总览 + 13 个功能模块详细设计；
3. **产品与后端资产说明（根目录）**——`info.md` 项目铁律与真实数据资产清单、`enforcement-review-expert-team_仓库梳理分析.md/.docx` 对 AI 专家团队仓库的梳理与产品布局对照。

一句话：**这是一套"大脑（AI 专家系统）已就绪、脸（前端界面）刚起骨架"的生态环境执法平台资料包**，核心价值在于极其完整的设计文档和真实业务数据资产，而非可运行代码。

## 三、前端代码现状诊断（关键发现）

`app/package.json` 显示技术栈：React 18.3 + Vite 5.4 + TypeScript 5.5 + oxlint 0.10 + lightningcss，**零额外 UI 库**（符合"纯 CSS 不加 Tailwind"铁律）。

`app/src/App.tsx`（218 行）已写出主框架逻辑（`makeInitialCases`、veto 扫描、百卷精评进度、左右中三栏装配、回调钩子），但**它 import 的文件在压缩包中全部缺失**：

| App.tsx 引用 | 实际是否存在 |
|---|---|
| `./components/LeftNav` | ❌ 缺失 |
| `./components/MiddleWorkArea` | ❌ 缺失 |
| `./components/modules/RightPanel` | ❌ 缺失 |
| `./data/enterprises` `vetoItems` `docTemplates` `knowledgeBase` `platforms` `discretionTables` | ❌ 全部缺失 |

**结论**：
- 当前 `app/` 是**无法 `npm run build` / `npm run type-check` 通过的残缺骨架**——缺 3 个核心组件目录 + 6 个数据层模块，TS 编译会直接报 "Cannot find module"。
- 已写出的 `App.tsx` 更像一份"界面契约/概念验证"：它假定了 data 层的导出形状（`Enterprise`、`VetoItem`、`ScanHit`、`DocTemplate`、`BizPlatform`、`DiscretionTable` 等接口），可作为后续补建 data 层的接口规范。
- 演示数据（赢湖矿产品 C-0072、鑫鑫环保建材 C-0071、金富源水污染案 C-0073）为草创示例，与设计文档反复标注的实战案卷（金竹山矿业、鑫顺建材、瑞龙木艺厂等）**命名不完全一致**，需在 data 层统一。

## 四、设计体系深度解析（最成熟、最具价值的部分）

设计文档是这套资料的核心资产，专业度可对标正规设计系统。要点：

### 4.1 设计语言基调
低饱和暖色、充足留白、层级清晰、非技术化语言（禁止对执法人员出现"模型/token/MCP 协议"等黑话）。面向**一线执法人员长时间使用**这一场景做了专门取舍。

### 4.2 色彩系统（精确到 hex）
- 基础色：暖米白底 `#F7F4EE`、左导航深暖褐灰 `#3E3831`、选中陶土橙 `#C97C3E`、右栏暖浅灰 `#F1EDE6`、分割线 `#E4DDD2`。
- 文字三级：`#2E2A26` / `#6E665C` / `#9A9184`。
- 功能色（全低饱和）：陶土橙（主强调）、橄榄绿 `#7C8B5F`（通过/正常）、赤陶红 `#B0574A`（否决/告警）、琥珀 `#C9A24B`（待办/临期）、灰蓝 `#6E8299`（AI/信息）、紫灰 `#8A7A9B`（审阅/批注）。
- 规则：大面积只用基础色；功能色同屏 ≤3 种；状态色一律配文字标签（适老/长时间可读性）。

### 4.3 字体与排版
- 字体栈：PingFang SC / Microsoft YaHei / Noto Sans SC / system-ui；数字用 `tabular-nums`（案号、日期、数据表）。
- 字号阶梯清晰：页面标题 20px / 区块 15px / 卡片 14px / 正文 13px·行高 1.7 / 辅助 12px / 看板数字 28–32px。

### 4.4 三栏布局
- 左导航 232px（`#3E3831`）+ 中间工作区 flex:1（min 640px）+ 右协作栏 320px（`#F1EDE6`）。
- 响应式：≥1440 三栏全显；1280–1439 右栏收窄 280px；<1280 右栏变抽屉（遮罩 30% 黑）。
- 左导航 12 模块顺序严格固定：执法助理 / 工作日历 / 辖区地图 / 企业管理 / 平台管理 / 执法办案 / 督察管理 / 案卷评查 / 档案管理 / 知识库 / MCP连接 / 设置（带角标的 4 个：执法助理、平台管理、案卷评查、工作日历）。

### 4.5 共享组件与动效
- 组件库：按钮（主/次/文字三型）、状态徽章（5 语义）、AI 专家芯片（9 专家统一）、SOP 五阶段条、进度条、卡片、空态、Toast、toggle。
- 动效克制、办公向：页面切换 280ms、列表 stagger 40ms、数字 count-up 600ms；**全站唯一重动效是"一票否决逐行扫描"**；尊重 `prefers-reduced-motion`。

## 七、一致性与矛盾核查

- ✅ **文书模板数量自洽**：info.md "73+1" = design.md "74" = 仓库梳理 "74 个"，表述不同但一致。
- ✅ **百卷精评进度一致**：design/review.md "73/100"、assistant.md "已评73卷"、App.tsx `hundredProgress.done=73` 三处吻合。

- ⚠️ **演示数据与实战案卷名不一致**：App.tsx 用"金富源水污染案/鑫鑫环保建材"，设计文档反复用"金竹山矿业/鑫顺建材/瑞龙木艺厂"，属 data 层草创期，需在补建 data 时统一。

## 八、关键发现与风险清单

1. **【阻断级】前端残缺**：`app/` 缺 components/ 与 data/，无法直接构建运行。需按 App.tsx 隐含的接口契约补建 6 个 data 模块 + 3 个组件目录，工作量集中在界面实现而非设计。
2. **【数据层空白】**：所有业务数据（企业、否决项、模板、法规、平台、裁量表）需在 `src/data/` 构造，目前只有占位与示例。
3. **【命名一致性】**：演示企业名需与 info.md/设计文档的实战案卷对齐，否则演示时数据对不上。
4. **【中文文件名编码】**：源 zip 文件名 GBK 编码，若用系统 `unzip` 会乱码（已修复）；后续若重新分发需备注。
5. **【文档 vs 代码时差】**：设计文档成熟度高，但前端仅 0-1 骨架，二者存在明显进度差——设计超前、实现滞后。

## 九、总体评价与下一步建议

**评价**：这是一份**设计驱动型**资料包。14 份设计文档构成了一套完整、专业、可直接落地的设计系统；后端数据资产（9 专家/28 技能/25 否决/74 模板/法规库/实战案卷）真实可用且经检验；前端目前是"有契约、缺实现"的骨架。

**建议优先级**：
1. 补建 `src/data/` 六个模块（以 App.tsx 接口为契约），先让 `type-check` 零错误；
2. 实现 `components/LeftNav` + `MiddleWorkArea` + `RightPanel` 三大容器，跑通三栏；
3. 优先落地最成熟模块「案卷评查（25 项否决扫描）」与「执法助理」首页，形成可见闭环；
4. 统一演示数据命名，对齐 info.md 实战案卷；
5. 其余 11 个模块按 design 文档逐页实现。

> 一句话收尾：资料包的"设计蓝图"已经画得非常漂亮，"施工图纸"也齐了，现在缺的是按图把墙砌起来的人。
