# Skill vs 提示词：本知识库的分工逻辑（2026-07-16）

## 一句话定位
- **Skill（eco-review-kb）= 导航层**：系统自动加载，管"去哪、走哪条路、跨文档怎么编排"。
- **提示词（一键提示词）= 执行层**：人手动复制，管"直接开干、产出什么、团队复用"。

## 两者不是二选一，而是分层协作
Skill 负责"认知/导航/流程编排"（自动、系统级）；
提示词负责"执行/产出/可移植复用"（主动、人触发）。

## 何时用 Skill（自动触发，一般不用你手动调）
1. 一句话触发：用户说"评查这份案卷/随督察现场/法典8-15衔接"等 → 触发词命中，系统自动加载路由。
2. 不确定从哪开始：Skill 先读 MOC（00-能力地图.md）定位目标文档。
3. 跨多 SOP 编排：如评查一般处罚案卷需依次调 25项一票否决→采样→证据链→程序→送达，Skill 编排调用顺序。
4. 法律临界硬约束：结案日期 ≥ 2026-08-15 的案卷，Skill 强制先查「法典8-15施行倒计时看板」（这是 Skill 的硬规则，提示词做不到）。
5. 团队协作标准化：Skill 保证每次都走同一套 SOUL v5.0 方法论。

## 何时用提示词（手动复制，主动发起）
1. 已定位到具体文档、明确要做某个具体任务（如"扫红线""逐项评分""双视角败诉预判"）→ 直接复制对应提示词（P1–P10）。
2. 批量分发给团队：提示词是可移植的独立文本，复制即走，保证口径一致。
3. 不想让模型重新推导指令：提示词封装了成熟任务的完整指令，省 token、保一致。
4. 重复执行同类任务：如每天评查几本案卷，存好提示词反复套用。

## 实际工作流（举例）
用户："评查这份案卷"
→ Skill 自动路由到 `03-实战全流程/一般行政处罚案卷评查.md`
→ 文档内嵌"第一步先扫25项一票否决"并附 P1 提示词
→ 你复制 P1 提示词 + 粘贴案卷要素
→ 产出 📋 红线扫描报告

## 关键边界
- Skill 管"路径正确性"（不会走错文档、不会漏红线）；
- 提示词管"产出一致性"（同一提示词跑十次，输出格式不变）。
- 法律临界类红线只能由 Skill 强制拦截，提示词只是执行工具，无强制力。
