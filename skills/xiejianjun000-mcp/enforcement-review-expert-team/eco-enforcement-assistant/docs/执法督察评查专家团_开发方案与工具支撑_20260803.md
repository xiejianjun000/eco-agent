# 执法督察评查专家团 — 开发方案与工具支撑

**编制日期**：2026-08-03 | **依据**：eco-enforcement-assistant 项目深度分析

---

## 一、现状诊断：从"单兵作战"到"专家团"的跃迁

eco-enforcement-assistant 当前是一个**单 Agent 工作空间**，虽然内容极其专业，但架构上存在明显瓶颈：

| 维度 | 当前状态 | 瓶颈 |
|------|---------|------|
| 架构 | 单 Agent（SOUL.md 定义单一角色） | 一个大脑承载所有能力，无法并行 |
| 任务执行 | 串行（每日 cron 依次触发） | 案卷评查 + 督察 + 巡检不能并发 |
| 知识管理 | 文件堆积（memory/ + 知识库/） | 缺乏结构化索引和智能检索 |
| 工具调用 | 原始脚本（需人工触发） | 无统一工具编排层 |
| 协作 | 无 | 各能力模块无法互相调用 |

**"专家团"的本质**：从单一 AI Agent 升级为 **多 Agent 协作系统**，每个 Agent 专注一个领域，通过统一编排层协作完成复杂执法任务。

## 二、专家团架构设计

### 2.1 核心架构：1 + 8 + N

```
                        ┌─────────────────────┐

                        │  (Orchestrator)      │
                        └──────┬──────┬───────┘
               ┌───────────────┤      ├───────────────┐
               ▼               ▼      ▼               ▼
        ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
        │案卷评查  │   │现场执法  │   │督察实战  │   │法律合规  │
        │ 专家     │   │ 专家     │   │ 专家     │   │ 专家     │
        └──────────┘   └──────────┘   └──────────┘   └──────────┘
        ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐

        └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

### 2.2 八大专家 Agent 定义

#### Agent 1: 案卷评查专家（Case Review Expert）
| 属性 | 内容 |
|------|------|
| **继承来源** | 当前 SOUL.md 案卷评查专家 v6.0 核心能力 |
| **核心职责** | 案卷合法性审查、一票否决扫描、规范性评分、败诉风险识别 |
| **关键知识** | 25 项一票否决清单、评查细则 2024 版、湖南省裁量权基准 |
| **输入** | 案卷文本（PDF/DOCX/TXT）、OCR 结果 |
| **输出** | 结构化评查报告（含法条引用、评分、扣分项、整改建议） |

#### Agent 2: 现场执法专家（On-site Enforcement Expert）
| 属性 | 内容 |
|------|------|
| **继承来源** | eco-enforcement-skill（1-6 部分：水/气/固废/噪声/采样/装备） |
| **核心职责** | 现场核查清单生成、执法程序合规指引、证据链设计 |
| **关键知识** | HJ 标准体系、10 大行业执法要点、9 种异常信号识别 |
| **输入** | 企业基本信息 + 线索类型（超标/偷排/造假） |
| **输出** | 现场核查清单、执法程序检查表、装备清单、取证要点 |

#### Agent 3: 督察实战专家（Inspection Combat Expert）
| 属性 | 内容 |
|------|------|
| **继承来源** | memory/模拟督察经验库/（11 篇） + SOUL.md 督察实战顾问 |
| **核心职责** | 模拟督察推演、下沉督察方案、典型案例分析、博弈策略 |
| **关键知识** | 督察制度逻辑、企业博弈应对、软性抵制识别、系统循环图 |
| **输入** | 督察任务（区域/行业/专题） |
| **输出** | 督察方案、前置分析报告、典型案例集、反馈意见、督办清单 |

#### Agent 4: 法律合规专家（Legal Compliance Expert）
| 属性 | 内容 |
|------|------|
| **继承来源** | MEMORY.md 法律知识 + 案卷评查知识库（法典全文 + 9 部单行法） |
| **核心职责** | 法律条文精准检索、法典过渡期衔接、移送公安标准判定 |
| **关键知识** | 1242 条法典全文、9 部单行法、裁量权基准、行刑衔接标准 |
| **输入** | 违法事实描述 + 适用法律检索需求 |
| **输出** | 法条引用（含法典双标注）、违法定性分析、移送公安判定、处罚裁量建议 |

#### Agent 5: 文书生成专家（Document Generation Expert）
| 属性 | 内容 |
|------|------|
| **继承来源** | gen_checklist.js + make_xcjc.py + make_xcjc_table.py |
| **核心职责** | 执法文书自动生成（现场监察记录、核查清单、评查报告） |
| **关键知识** | 文书模板库、Word/PDF 生成、格式规范 |
| **输入** | 结构化数据（案件信息、检查结果、评查结论） |
| **输出** | .docx 格式执法文书（彩色封面、分级标题、表格、法律依据速查） |

#### Agent 6: 数据分析专家（Data Analysis Expert）
| 属性 | 内容 |
|------|------|
| **继承来源** | raw/ 案例数据 + 水环境平台巡检 + CEMS 数据深度分析 |
| **核心职责** | CEMS 数据研判、超标分析、水平衡异常检测、案例统计分析 |
| **关键知识** | 在线监测数据特征、造假模式识别（峰谷操作/稀释/参数篡改） |
| **输入** | CEMS 数据 CSV、平台 API 数据、案例 JSON |
| **输出** | 数据异常报告、超标逐条核查、造假信号排查、统计分析图表 |

#### Agent 7: 知识库管理专家（Knowledge Base Manager）
| 属性 | 内容 |
|------|------|
| **继承来源** | _migrate_lib.py + MCP知识库短板补齐报告 + 入库全链路跑通 |
| **核心职责** | 知识库维护、法律法规更新、案例入库、知识检索 |
| **关键知识** | LLM Wiki 方法论、MCP 知识库接入、法典更新追踪 |
| **输入** | 新法规/案例/政策文件 |
| **输出** | 入库记录、更新日志、知识图谱、检索结果 |

#### Agent 8: 平台巡检专家（Platform Patrol Expert）
| 属性 | 内容 |
|------|------|
| **继承来源** | water-platform-inspect 系列 + 大气监督帮扶平台登录分析 |
| **核心职责** | 水环境平台每日自动巡检、监督帮扶平台任务跟踪 |
| **关键知识** | Playwright CDP、ddddocr 验证码、平台 API 协议 |
| **输入** | 平台登录凭证、巡检计划 |
| **输出** | 巡检报告（新任务/状态变更/超期告警/对比结论） |

## 三、工具支撑体系

### 3.1 已有工具（可直接复用）

| 类别 | 工具 | 用途 | 来源文件 |
|------|------|------|---------|
| 🔌 **MCP 连接** | MCP-over-SSE 客户端 | 连接远程 EHS 知识库，批量检索案例 | `mcp_session.py` / `mcp_sse_client.py` |

## 四、分阶段实施路线图

### 第一阶段：核心 Agent 激活（1-2 周）

```
目标：将 3 个最成熟的专家 Agent 独立运行
```

| 任务 | 产出 |
|------|------|
| 1. 从 SOUL.md 拆分出案卷评查专家独立 Agent | Agent 定义 + 独立记忆 + prompt |
| 2. 从 eco-enforcement-skill 拆分出现场执法专家独立 Agent | Agent 定义 + 独立记忆 + prompt |
| 3. 从 MEMORY.md + 案卷评查知识库 拆分出法律合规专家独立 Agent | Agent 定义 + 独立记忆 + prompt |
| 4. 搭建基础 Orchestrator（任务分发 + 结果聚合） | 编排层代码 |
| 5. 三个 Agent 独立跑通评查→执法→合规协作流程 | 端到端验证 |

### 第二阶段：工具链补齐（2-3 周）

```
目标：为每个 Agent 配备专用工具
```

| 任务 | 产出 |
|------|------|
| 1. 统一知识检索 API（RAG） | 跨库检索服务 |
| 2. 案卷智能解析器 | 自动解析 PDF → 结构化案卷 |
| 3. 法律条文智能匹配 | 违法事实→精确法条 |
| 4. 文书模板引擎 | 参数化文书生成 |
| 5. CEMS 数据研判引擎 | 在线监测异常检测 |

### 第三阶段：全团联动（2-3 周）

```
目标：8 个 Agent 全部就位，协作完成复杂任务
```

| 任务 | 产出 |
|------|------|
| 1. 激活剩余 5 个 Agent（督察/文书/数据分析/知识库/平台巡检） | 8 个 Agent 全部上线 |
| 2. 实现多 Agent 串并联协作流程 | 协作协议 + 消息总线 |
| 3. 统一 API Gateway | FastAPI 对外接口 |
| 4. 定时任务系统 | APScheduler 每日自动化 |
| 5. 质量评估体系（红蓝对抗 + 评分基准） | 质量保障机制 |

## 五、技术架构建议

### 5.1 推荐技术栈

```
专家团编排层
├── LangGraph（多 Agent 编排）← 军哥已有基础
├── CrewAI（备选方案，更轻量）
└── 自定义 Orchestrator（如果深度定制）

知识层

├── 案卷评查知识库（Markdown，~98 文件）

工具层

├── Playwright（浏览器自动化）
├── ddddocr（验证码识别）

基础设施
├── Git + GitHub（版本管理）
├── APScheduler（定时任务）
├── Obsidian Vault（知识可视化）
└── 日志系统（已有 memory/ 结构可复用）
```

### 5.2 与 EcoMind OS 的融合

军哥的 EcoMind OS 已具备：
- **TAIJI-AGENT 2.0**（112 模块）
- **LangGraph + CrewAI 双引擎编排**
- **四层记忆系统**
- **FastAPI 后端 + React 18 前端**
- **11 个 API 路由器（54 端点）**

**融合路径**：
1. 八个专家 Agent 作为 EcoMind OS 的**领域 Agent 模块**接入 TAIJI-AGENT
2. 知识库接入 EcoMind 四层记忆系统的**知识层**
3. 工具脚本封装为 MCP Server，接入 EcoMind 工具层
4. 前端新增"执法督察专家团"三栏界面面板

## 七、总结

eco-enforcement-assistant 项目积累的核心资产（SOUL.md 人格体系、MEMORY.md 知识沉淀、eco-enforcement-skill 技能定义、案卷评查知识库、8 个 Python/JS 工具脚本、水环境平台巡检自动化），为构建"执法督察评查专家团"提供了 **90% 的原材料**。

**关键突破点**：
1. 从**单 Agent** 拆分为 **8 个领域专家 Agent**（架构跃迁）
2. 补齐**多 Agent 编排引擎 + 统一知识检索 + 案卷智能解析**三大核心工具
3. 与 **EcoMind OS 现有架构**深度融合，而非另起炉灶
