## 一、原文方法论内核（去营销化提炼）

核心命题："真正的工作，很少能靠一句 Prompt 解决。真正稀缺的，是一套围绕真实任务、能一步步跟着完成的专业工作方法。"

TRAE Work 知识库 6 大板块 → 迁移映射：
- 能力地图/快速导航 → 评查能力全景图 + 场景入口
- 新手入门（17篇） → 第一次评查/第一次督察怎么做
- 官方功能教程（14篇） → 单项能力SOP（采样审查/证据链核验）
- 实战教程（7场景30+篇，40w字）→【核心】6类案卷评查全流程
- 工具资源推荐 → 评查清单/文书模板/法条库
- 近期活动 → 法律更新预警

三条设计铁律：
1. 从任务出发，不从功能出发（用户直接找"我要评查危废案卷"）
2. 走完一条完整工作流（目标拆解→资料准备→发起→过程检查→结果优化→交付）
3. 知识直接变成成果（边学边做，直接产出报告/文书）

## 二、LLM Wiki 方法论要点

- 原子化：一个概念/SOP = 一个文件
- 渐进披露：索引(MOC) → 主题 → 细节
- 结构化元数据：frontmatter（触发词/适用场景/关联法条/更新日期）
- 双向链接：形成知识网
- 检索优化：标题即关键词、结论前置、法条精确到条款项
- 任务锚点：每篇有"何时读我"触发信号（SKILL.md 写法）

## 六、引擎层：Skills + 提示词怎么用（2026-07-16补充）

### 三层分工
- 知识库文档 = 作战地图（该怎么做）→ 03-实战全流程等
- 提示词 = 作战命令（怎么让LLM开始做）→ 每篇内嵌 + 05-工具资源/提示词库
- Skill = 执行部队（自动执行的可复用程序）→ 现有eco-enforcement等3个skill

### Skills 用法
1. 每篇文档 frontmatter 增加 `调用skill:` 字段，正文步骤写明触发点
2. 知识库触发词复用 skill 的触发词表，形成 skill找方法→方法引导执行 闭环
3. 终局：把 eco-review-kb 打包成新skill，SKILL.md 作总路由（仿 eco-enforcement-platform）

### 提示词用法
- 形态A 内嵌式：每篇文档结尾加「▶️一键提示词」区块，复制即发起
- 形态B 模板库式：05-工具资源/提示词库/（评查类/督察类/文书类），带变量占位符
- 编写4要素：【场景】+【要求/标准(引法条到条款项)】+【材料占位】+【输出格式】

### 协同调用链示例
用户说"评查危废案卷" → ①触发词命中platform skill路由 → ②read实战文档 →
③文档给流程/清单/扣分点 → ④调用SOP+法条库 → ⑤复制内嵌提示词发起 → ⑥输出⚖️报告
