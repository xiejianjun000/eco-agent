# ECO AGENT Desktop 前端设计宪法

> G1: 宪法治理 — 先立规则再写代码
> G2: 工具化思维 — 单一职责
> G6: 职责分离 — 知识层与逻辑层解耦
> G8: 可追溯 — 每次操作可回源

---

## 一、设计哲学

**这不是"聊天工具"，而是"环境治理专业工作台"。**

核心问题：执法人员打开 ECO AGENT，应该**直接干完一整件事**——从发现线索 → 分析研判 → 生成文书 → 归档留痕，全程不被工具切换打断。

因此界面不是"功能列表"，而是**任务流**。

## 二、信息架构（G6 职责分离）

```
┌──────────┬────────────────────────────┬──────────────┐
│          │                            │              │
│ 左侧导航  │      中央工作区             │  右侧上下文   │
│  (身份)   │      (任务主战场)           │   (情报)      │
│          │                            │              │
│ 模块      │  当前任务的                │  动态面板：    │
│ 本地/云端 │  - 文档/案卷               │  - 对话提取   │
│ 智能体状态│  - 地图/图纸               │  - 产出物     │
│          │  - 浏览器页面              │  - 工具调用    │
│          │                            │  - 进化记录   │
├──────────┴────────────────────────────┴──────────────┤
│                 底部：命令中心 + 状态                    │
└───────────────────────────────────────────────────────┘
```

### 职责边界

| 区域 | 职责 | 禁止 |
|:-----|:-----|:-----|
| **左侧导航** | 身份/模块切换/模式 | 不做任务细节 |
| **中央工作区** | 当前任务的主视图 | 不堆辅助工具 |
| **右侧上下文** | 情报与产出（AI 实时） | 不承载主编辑 |
| **底部命令中心** | 输入 + 状态 + 快捷操作 | 不承载内容展示 |

## 三、关键设计决策

### 3.1 输入框放哪？→ 底部"命令中心"

**设计**：底部不再是纯状态栏，而是**"命令中心"（Command Center）**——输入框 + 状态 + 快捷操作融合。

```
┌─────────────────────────────────────────────────────┐
│ [⚡ 输入指令或问题.....................] [发送] [🎤] │
│ 智能体:待命 · 工具:113 · 同步:正常 · 模式:云端      │
└─────────────────────────────────────────────────────┘
```

**为什么**：
- 输入是**全局动作**（问 AI、命令执行、搜索），不属于任何单模块
- 让输入框常驻底部，符合肌肉记忆
- 输入时自动感知当前模块上下文（在执法模块输入 → 自动代入案卷语境）
- 状态信息与命令入口合一，减少视觉噪音

### 3.2 右侧栏怎么设计？→ "情报面板"（动态上下文）

右侧栏不是固定内容，而是**随当前任务动态加载的"情报面板"**，顶部标签切换：

```
┌──────────────────┐
│ 💬 对话 │ 📦 产出 │ 🔧 工具 │ 🧬 进化 │
├──────────────────┤
│  当前标签内容     │
│                  │
│  [对话] 多轮提取  │
│  AI 分析结果      │
│  引用来源         │
│                  │
│  [产出] 生成的    │
│  报告/图表/文书   │
│  一键插入文档     │
│                  │
│  [工具] 文档编辑器 │
│  浏览器/画图      │
│  按需加载         │
│                  │
│  [进化] 经验沉淀  │
│  技能改进记录     │
└──────────────────┘
```

**右侧栏四个标签的职责**：

| 标签 | 内容 | 何时激活 |
|:-----|:-----|:---------|
| **💬 对话提取** | 多轮 AI 对话 + 结构化结论提取 | 始终 |
| **📦 产出物** | 生成的报告/文书/图表，可插入文档 | AI 生成后 |
| **🔧 工具** | 文档编辑器/浏览器/画图（嵌入式） | 用户需要时 |
| **🧬 进化** | 智能体反思、技能改进、经验沉淀 | 有进化事件时 |

### 3.3 工具如何嵌入？→ "工具抽屉"模式

文档编辑器、网站浏览器、画图编辑器不常驻，而是**按需滑出**：

```
中央工作区                       右侧情报面板
┌──────────────────────┐  ┌──────────────────┐
│ 案卷文档 (ONLYOFFICE) │  │ 💬 对话提取       │
│                      │  │  - AI 评查结果    │
│  ← 主编辑区           │  │  - 引用条款       │
│                      │  └──────────────────┘
└──────────────────────┘  ┌──────────────────┐
                          │ 🔧 工具抽屉(滑出)  │
                          │  - 浏览器标签      │
                          │  - 画图工具栏      │
                          └──────────────────┘
```

**触发方式**：
- 在文档中选中"某企业"→ 右键 → "地图定位" → 地图在右侧工具抽屉打开
- 在对话中问"查一下许可证"→ 浏览器工具自动打开并导航
- 需要画现场图 → 画图工具在右侧抽屉激活，画完自动回填文档

## 四、事件总线（G8 可追溯）

所有跨模块操作走统一事件中心：

```typescript
// events.ts
interface EcoEvent {
  type: string        // 'navigate' | 'open-doc' | 'map-locate' | 'generate' | ...
  source: string      // 来源模块
  payload: any        // 数据
  traceId: string     // 可追溯 ID
}

// 示例
bus.emit('map-locate', { company: 'XX化工', lat: 28.9, lng: 111.7 })
bus.emit('open-doc', { path: '/cases/xx.docx' })
bus.emit('generate-report', { module: 'enforcement', caseId: 'xxx' })
```

**这保证**：
- 监测模块发现超标 → 右键"溯源" → 事件总线 → 大气模块自动打开并代入参数
- 对话生成报告 → 事件总线 → 产出物面板显示 → 一键插入文档
- 每次操作留 traceId，可追溯完整链路

## 五、模块契约（G2 单一职责）

每个模块实现标准接口：

```typescript
interface EcoModule {
  id: string
  title: string
  icon: string
  enter(ctx: ModuleContext): void      // 进入模块时
  exit(): void                          // 离开模块时
  onEvent(e: EcoEvent): void            // 接收总线事件
  render(): React.ReactElement          // 主视图
}
```

**这让模块间彻底解耦**——执法模块不知道监测模块的存在，只通过事件总线通信。

## 九、人机协同编辑宪法（G1 新增）

> 核心问题：AI 如何与人类在同一个文档上协作，既高效又不失控？

### 9.1 三种协同模式

| 模式 | 触发 | 流程 |
|:-----|:-----|:-----|
| **AI 主动标注** | 打开文档自动评查 | AI 高亮问题 → 右侧列批注 → 人类逐条确认 |
| **人类手动标注** | 选中文字添加 | 人类标记 → AI 可响应补充 |
| **双向对话** | 批注中提问 | 人类问 → AI 答 → 产出物插入 |

### 9.2 批注类型（ANNOTATION_TYPES）

| 类型 | 图标 | 颜色 | 含义 |
|:-----|:-----|:-----|:-----|
| error | 🔴 | #f04040 | 明确错误/违法事实 |
| warning | 🟠 | #f0a040 | 疑似问题/程序瑕疵 |
| suggestion | 🔵 | #40a0f0 | 改进建议 |
| question | 🟣 | #a040f0 | 疑问/待核实 |

### 9.3 批注状态机（G4 质量门禁）

```
pending ──接受──→ accepted（应用到文档）
   │  ──拒绝──→ rejected（高亮消失）
   │  ──修改──→ edited（人工改后应用）
   └─（关闭）──→ deleted
```

### 9.4 操作契约（G8 可追溯）

- 每条批注必须有：`traceId` / `source`（ai|human）/ `createdAt`
- 每次接受/拒绝/修改必须记录：操作者 / 时间 / 变更前后
- 批注数据不可变：状态变更生成新记录，不覆盖原数据

### 9.5 文档渲染规则

- AI 高亮：`背景色22%透明度 + 底部2px彩色下划线`
- 选中批注：背景色加深至 `33%透明度`
- 鼠标悬停：显示批注气泡（note 内容）
- 已接受：应用建议文本，批注变绿
- 已拒绝：恢复原文，高亮消失

### 9.6 文本变更后的位置校正

- 接受/修改导致文本长度变化 → 后续批注 start 自动偏移
- 规则：`新位置 = 原位置 + (新文本长度 - 原文本长度)`
- 保证批注不因编辑而错位（G6 职责分离）

### 9.7 组件职责（G2 单一职责）

| 组件 | 职责 |
|:-----|:-----|
| `types/annotation.ts` | 数据模型 + 纯函数（不依赖 React） |
| `CollaborativeEditor.tsx` | 渲染引擎 + 状态管理 |
| `AnnotationSidebar.tsx` | 批注列表 + 操作按钮 |
| `ActivityPanel.tsx` | 容器（嵌入编辑器 + 侧栏） |

### 9.8 验收标准

- [ ] 打开文档自动 AI 评查，8秒内出批注
- [ ] 人类可接受/拒绝/修改任意批注
- [ ] 接受后文档立即应用修改
- [ ] 修改后后续批注不错位
- [ ] 每条操作可追溯（traceId + 时间）
- [ ] 人类可手动选中文字添加批注
- [ ] AI 批注与人类批注可区分（🤖/👤）
